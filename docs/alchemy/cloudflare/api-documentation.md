# API reference and OpenAPI

The assembled `Api` in `apps/api/src/api/api.ts` is the source of truth. It composes contracts owned by `apps/api/src/api/<group>.ts`; the health contract currently lives in `apps/api/src/api/healthz.ts`. Effect generates the specification from endpoint schemas, declared errors, security, and annotations. Describe public behavior in those contracts rather than editing generated output.

`apps/api/src/server/http.ts` registers both `/api/openapi.json` and `/api/docs` using Effect's HttpApiBuilder and bundled HttpApiScalar. Scalar supplies the interactive UI and request testing; there is no custom documentation frontend. Default font downloads are disabled. Both routes live under `/api/*` so Cloudflare's existing runWorkerFirst asset policy routes them through the Worker.

Run `bun run api:export` from the repository root to write `generated/openapi.json` without connecting to Cloudflare. CI exports and uploads it as the `openapi` artifact. This enables downstream generators without maintaining a second API definition. The generated directory is ignored; no generated SDK or CLI is installed or published yet.

`GET /llms.txt` serves concise project context and links to the OpenAPI document and Scalar reference. Its contract lives in `apps/api/src/api/llms.ts` and its handler lives in `apps/api/src/server/llms/http.ts`. Links use the current request origin, so local, preview, production, and custom domains need no configured hostname. `apps/api/src/api/documentation.ts` owns the paths shared by router registration and discovery links. The Worker's `runWorkerFirst` policy includes `/llms.txt` so frontend assets cannot intercept discovery.

Keep endpoint paths, methods, payloads, responses, errors, and authentication requirements in their owning API contracts. Discovery links to those specifications instead of duplicating their content. When adapting the template, update the project heading and summary in the discovery handler. This endpoint follows the [llms.txt proposal](https://llmstxt.org/); an API catalog is not included.

Whole-app tests in `apps/api/tests/worker.test.ts` start the actual Worker in local workerd through Alchemy’s Effect-aware test harness. Build frontend assets with `bun run build` before running `bun test apps`. Tests fetch the documentation routes over HTTP, compare the served specification with the assembled contract, and verify that Scalar HTML contains the contract and bundled script. The test stack uses isolated local state and is destroyed after the suite; no Cloudflare deployment is required. These checks do not exercise browser rendering or the interactive request button. API compatibility diffing and SDK/CLI generation remain separate future additions.

References: [Effect HttpApiBuilder](https://effect.website/docs/v4/api/effect/http-api/HttpApiBuilder), [Effect Scalar integration](https://effect.website/docs/v4/api/effect/http-api/HttpApiScalar), and [Cloudflare Forge](https://github.com/cloudflare/forge). Forge currently describes its CLI as the first output and other generation targets as developing; reassess its support before adopting it.
